运行日志 app.log

Gitwo 把每个服务的标准输出与标准错误追加到运行目录的 app.log， 并在仓库页提供分页查看（按仓库鉴权、从文件尾向前翻）。

app.log 是什么

服务启动命令实际是 setsid nohup <run.command> >> app.log 2>&1 &，所以：

项目说明
内容服务进程的 stdout + stderr 合并，没有平台加的时间戳/前缀，格式由程序决定
文件名固定为 app.log，与 build.backend.output 无关（output 只决定安装后的二进制名）
位置服务运行目录 run.workdir：缺省 <程序目录>/apps/<归属_仓库>/app.log
写入方式>> 追加：每次部署/重启都往同一个文件末尾写，平台不轮转、不截断
生命周期在 apps/ 下，跨部署、跨 Gitwo 重启都保留（工作区才是每次清空的）
哪些输出会进来：Go log/slog、zap/logrus 的 console 输出、Java System.out/err、 Python print/logging.StreamHandler、任何写 fd 1/2 的内容。 程序自己写到文件（如 logs/app.log、logback FileAppender、lumberjack 轮转文件）的日志不会出现在这里。

在哪里看

Web 界面：仓库页 →「运行日志」标签；或直接访问 /repos/<归属>/<仓库>/logs。

项目说明
可见范围登录的开发者/管理员，且对该仓库有读权限；测试角色与匿名不可见（运行日志可能含路径、配置、连接串等敏感信息）
隔离按仓库隔离，只显示当前仓库的 app.log，没有全局日志视图
静态站点仓库type: static 没有常驻服务，没有 app.log，页面会提示未部署服务
自定义 workdir日志位置跟着 run.workdir 走；部署时会把 workdir 写入描述符，老部署需要重新部署一次才会被日志页识别

分页机制（加载更早）

日志可能很大，查看器不会一次读全文件：

行为说明
从尾部开始首次打开显示最新一页（默认 200 行，单页最多读 256 KiB）
加载更早以本页第一行的字节偏移为游标向前再读一页，逐页追加到页面上
服务端成本每次只读一页（O(页大小)），与文件总大小无关；不缓存、不常驻内存
浏览器成本已加载的页会累积在页面里（点多少占多少）；「刷新最新」会丢弃已加载的更早内容、回到最新一页
JSON 接口GET /api/repos/<归属>/<仓库>/logs?before=&lines=：返回 lines/start/end/has_more/size，可直接脚本化取日志

与「任务日志」的区别

运行日志 app.log任务日志（流水线日志）
内容服务进程运行时输出一次部署的 git 同步 / 构建 / 安装 / 启动全过程
位置apps/<归属_仓库>/app.log/tmp/gitwo/logs/<归属_仓库>/<task>.log
查看入口仓库页「运行日志」标签流水线详情页（实时刷新）
保留策略一直追加，平台不轮转（需自行治理）每仓库保留最近 20 份
权限开发者/管理员（仓库可读）开发者/管理员（仓库可读），测试角色不可见

程序自带日志系统怎么处理

做法结果
日志写 stdout/stderr（框架默认，推荐）全部进 app.log，仓库页统一查看
写自己的文件（logs/xxx.log、logback FileAppender）业务日志在自己的文件里，app.log 可能只有启动日志或为空；平台不展示这些文件
自己轮转同名 app.log不推荐：程序 truncate/rename 会让 shell 重定向的 fd 指向旧 inode，输出与预期错位
同时写控制台和文件app.log 与自己的文件各一份，由程序保证一致
想让运行日志页看到全部业务日志，就把日志输出到 stdout/stderr；自定义文件日志请用独立文件名并自行轮转。 缓冲注意：Python 输出重定向到文件是块缓冲，建议 python3 -u 或 PYTHONUNBUFFERED=1； Go log、Java 的 println、stderr 一般即时写入。

常见问题

现象原因 / 处理
页面提示还没有 app.log仓库不是 service/dual、尚未部署成功，或服务从未启动过（启动即失败时请看流水线详情里的 app.log 尾部）
app.log 是空的程序不往 stdout/stderr 写日志（自带文件日志），或缓冲未刷新（见上）
找不到、但服务在跑自定义了 run.workdir 且未重新部署，日志页按旧描述符找；重新部署一次即可
文件越来越大平台不轮转：程序内轮转（如 lumberjack），或对 apps/*/app.log 配 logrotate（nohup 场景用 copytruncate，避免 rename 后输出继续写旧文件）
日志含敏感信息运行日志只对开发者/管理员开放；仍建议程序侧脱敏，或用 run.env 注入密钥而不是打印
