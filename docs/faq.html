常见问题

push 提示 Authentication failed / 403

账户密码错误，或该用户对 private 仓库无权限（需要是归属者/组织成员/管理员）。URL 中的用户必须是平台账户，不是系统用户。

SSH 提示 Permission denied (publickey)

公钥未在「账户设置 → SSH 公钥」登记；或一把钥匙已绑定其他账户；测试角色没有 git 权限。用 ssh -T -p 2222 git@host 可验证握手。

push 提示「主分支受保护」

组织仓库的主分支仅组织创建者/管理员可直接推送。请推送到自己的分支（git push origin HEAD:feature/xxx），由管理者合并。

流水线失败 no deploy.yaml / output not found

仓库根目录需有 deploy.yaml；检查构建命令输出与 output 路径是否一致，可在流水线详情查看每步日志。

流水线失败 run.files entry "…" not found

run.files 条目相对仓库根（构建工作区）解析，且工作区只包含已提交内容；确认文件已提交、在子目录时写全路径（如 configs/config.yaml），构建产物则写生成后的路径。单文件条目会同步到运行目录根（只保留文件名），要保留子目录结构请写目录条目。

服务启动后找不到 config.yaml 等配置文件

服务从 <程序目录>/apps/<归属_仓库>/（run.workdir）启动，不会从仓库工作区读文件；工作区每次部署都会 git checkout + git clean -fdx，是临时的。运行期需要的配置文件必须用 run.files 同步（如 files: [config.yaml]，文件需已提交或在构建期生成）。也不要把 run.workdir 指到工作区：下次部署会清掉 app.pid/app.log，旧进程停不掉、端口冲突。

怎么看服务运行日志（app.log）？

仓库页 →「运行日志」标签（或 /repos/<归属>/<仓库>/logs）：从文件尾向前分页查看，每页 200 行、「加载更早」可继续往前；权限与源码/流水线一致——仅仓库可读的开发者与管理员可见，测试角色与匿名不可见。日志文件位于服务运行目录 apps/<归属_仓库>/app.log（自定义 run.workdir 时为该目录，需重新部署一次以写入描述符）；只有服务的 stdout/stderr 会写进来，程序自带日志系统写出的其它文件不在此页。详见 运行日志。

服务部署后打不开

服务必须读取注入的 $PORT 监听；通过 /api/<仓库>/ 代理访问即可，无需暴露 20000-23999 端口。部署详情页会自动附 app.log 尾部。

如何备份 / 迁移？

数据全部是文件：拷贝整个程序目录（repos/ workspaces/ apps/ data/）即可，无数据库。任务日志在 /tmp 下，丢失不影响历史摘要。

安全提醒

deploy.yaml 的构建/启动命令以 gitwo 运行用户身份在宿主机执行——能 push 即等同该用户级命令执行权限。请只授予可信成员写权限，不要用 root 运行。
