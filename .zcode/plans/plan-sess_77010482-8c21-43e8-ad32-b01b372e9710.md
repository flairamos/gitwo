## Context

构建卡在依赖下载（如 `go mod download` 网络挂起）时，目前只能等满 `timeouts.build`（默认 10 分钟）才失败。用户要求：**构建命令连续 20 秒无任何输出即判定卡死，自动终止并报"超时"**（已确认：是"停滞检测"而非总时长 20 秒；仅对构建步骤生效，默认 20s 可配置）。

## 实现方案

### 1. `internal/shellutil/shellutil.go` — 增加停滞检测（核心）
- `runCmd` 增加 `stall time.Duration` 参数：用 `atomic.Int64` 记录最后输出时间（包装现有 stdout/stderr writer），watchdog goroutine 每 ≤1s 检查一次；**超过 stall 无输出** → 复用现有 `killGroup`（SIGTERM → 5s → SIGKILL）终止整个进程组。
- 新增 `ShellStall(ctx, dir, env, logw, stall, script)`；`Run/Output/Shell` 传 0 保持原行为。
- 新错误信息：`sh -c <cmd>: 停滞超过 20s（无任何输出，常见于依赖下载卡死或网络不可达），已终止`。
- `internal/shellutil/shellutil_windows.go` 同步加 `ShellStall` stub（与现有 `errUnsupported` 行为一致）。

### 2. `internal/appconfig/appconfig.go` — 配置项
- `Timeouts` 增加 `Stall *Duration `yaml:"stall"``：缺省 20s、显式 `0s` 关闭（沿用现有 `setDefaults` 模式与 unexported 解析字段 + `StallD()` 访问器）。

### 3. `internal/pipeline/pipeline.go` — 仅构建步骤启用
- `Timeouts` 结构加 `Stall time.Duration`；`buildBackend`/`buildFrontend` 两处 `shellutil.Shell(...)` 改为 `shellutil.ShellStall(..., p.Params.Timeouts.Stall, ...)`。
- git 同步/部署/启停步骤**不启用**（大仓库静默 clone 会被误杀）。

### 4. `main.go` — boot 传参
- `Params.Timeouts` 增加 `Stall: cfg.StallD()`。

### 5. 文档
- `configs/server.yaml.example`：`timeouts` 段加 `stall: 20s` 注释（含义、0 关闭、安静编译超 20s 的误杀提示）。
- `README.md`「多语言构建与运行」/故障排查：说明停滞检测行为与调整方法。

### 6. 测试与验证
- 新增 `internal/shellutil/stall_test.go`（`//go:build !windows`）：
  1. 静默 `sleep 5` + stall=300ms → 报错含"停滞"；
  2. 周期输出（每秒 echo）持续 2s + stall=500ms → 成功；
  3. stall=0 时静默命令正常完成（不回归）。
- 本机为 Windows，POSIX 路径用 `GOOS=linux go build ./... && GOOS=linux go vet ./...` 做编译验证；全量 `go test ./...` 保证无回归。
- Linux 服务器实测：构建命令 `sleep 30` → 20 秒即报"停滞超过 20s…已终止"；`for i in $(seq 10); do echo $i; sleep 1; done` → 正常通过。
